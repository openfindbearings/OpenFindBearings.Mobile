# Mobile BFF 认证集成设计 v1.0.0

## 概述

Mobile BFF 的认证体系基于 JWT Bearer，BFF 代理 Identity 的 OAuth 2.0 端点，前端只与 BFF 交互。BFF 不存储用户凭证，仅做请求转发和 token 代理。

## 变更日志

### v1.0.0 (2026-09-01)

- 初始版本，认证流程、token 刷新、device_id 绑定、401 重试策略。

## 认证架构

```
Taro 前端                    Mobile BFF                    Identity
────────                     ──────────                    ────────
POST /mobile/auth/login  ──► POST /connect/token       ──► 验证凭据
                         ◄── {access_token, refresh_token}
存储 token + deviceId

GET /mobile/* (Bearer)   ──► JWT 验证（Authority=Identity）
                         ◄── 200 OK / 401 Unauthorized

401 响应                 ──► POST /mobile/auth/refresh  ──► grant_type=refresh_token
                         ◄── {新 token}                     校验 device_id
重放原请求               ──► 用新 token 重试
```

## Token 类型

| Token | 存储位置 | 持久化 | 有效期 | 说明 |
|-------|----------|--------|--------|------|
| access_token | 前端内存变量 | 否 | 10 分钟 | 不写入持久存储，防泄露 |
| refresh_token | 本地存储 | 是 | 30 天 | 用于自动续期，绑定 device_id |
| device_id | 本地存储 | 是 | 永久 | 随机 GUID，登录时生成 |

## device_id 设备绑定

### 生成时机

用户首次打开应用时生成随机 GUID，存入本地存储（H5 用 localStorage，小程序用 Taro.setStorageSync）。

### 绑定流程

1. 登录时前端将 `deviceId` 随请求发送给 BFF
2. BFF 代理到 Identity 的 `/connect/token`，`device_id` 作为自定义参数传递
3. Identity 将 `device_id` 写入 JWT claim 和 refresh_token 绑定
4. 刷新时 Identity 校验 `device_id` 与签发时是否一致

### 设备隔离

- 每个设备独立登录，refresh_token 绑定 device_id
- 设备 A 的 refresh_token 不能在设备 B 上使用
- 刷新时 `device_id` 不匹配返回 `invalid_grant`

## 401 重试策略

```typescript
// Taro 前端 request.ts 中的重试逻辑
if (res.statusCode === 401 && auth && isTokenValid() === false) {
  const newToken = await tryRefreshToken()
  if (newToken) {
    // 用新 token 重放原请求
    header['Authorization'] = `Bearer ${newToken}`
    const retryRes = await Taro.request({ ... })
    return parseResponse<T>(retryRes)
  }
  // 刷新失败 → 清除 token，提示重新登录
  clearTokens()
  throw new Error('登录已过期，请重新登录')
}
```

### 重试条件

- 仅在 `auth=true` 的请求触发
- 仅重试一次，不循环重试
- 刷新失败立即清除本地 token

### 并发请求处理

多个请求同时收到 401 时，只发一次 refresh 请求。可选实现：用 Promise 缓存正在进行的 refresh 请求，后续 401 共享同一 refresh 结果。

## BFF JWT 验证

BFF 使用 ASP.NET Core JWT Bearer 中间件验证 access_token：

```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = "http://openfindbearings-identity:80"; // K8s 内部
        options.Audience = "api:mobile";
        options.RequireHttpsMetadata = false; // K8s 内部 HTTP
        options.TokenValidationParameters = new()
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
        };
    });
```

### 端点认证控制

| 模式 | 说明 |
|------|------|
| `AllowAnonymous()` | 公开端点，不检查 token |
| `RequireAuthorization()` | 需要有效 JWT |
| 默认（不指定） | 走全局 DefaultPolicy（需 JWT） |

## 登录流程详细

### 密码登录

```
前端 → POST /mobile/auth/login
  Body: { username: "手机号", password: "密码", deviceId: "GUID" }

BFF → Identity POST /connect/token
  grant_type=password
  username=手机号
  password=密码
  client_id=mobile-client
  client_secret=mobile-secret
  scope=api:mobile
  device_id=GUID

Identity → BFF → 前端
  { access_token, refresh_token, expires_in: 600 }
```

### 短信登录

```
1. 前端 → POST /mobile/auth/send-code
     Body: { phone: "手机号" }
   BFF → Identity POST /api/sms/send-code

2. 前端 → POST /mobile/auth/login-sms
     Body: { phone: "手机号", code: "验证码", deviceId: "GUID" }
   BFF → Identity POST /connect/token
     grant_type=sms
     username=手机号
     code=验证码
     device_id=GUID
```

### 令牌刷新

```
前端 → POST /mobile/auth/refresh
  Body: { refreshToken: "旧token", deviceId: "GUID" }

BFF → Identity POST /connect/token
  grant_type=refresh_token
  refresh_token=旧token
  client_id=mobile-client
  device_id=GUID
  // Identity 校验 device_id 与签发时是否一致
```

## 安全注意事项

- access_token 不持久化，仅存内存，防 XSS 窃取
- refresh_token 持久化但绑定 device_id，防跨设备盗用
- BFF 不存储任何凭证，仅做转发
- K8s 内部通信使用 HTTP（无需 TLS），公网域名使用 TLS
- BFF 的 CORS 仅允许 Taro H5 域名
