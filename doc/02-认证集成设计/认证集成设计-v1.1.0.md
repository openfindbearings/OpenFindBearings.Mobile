# Mobile BFF 认证集成设计 v1.1.0

## 概述

Mobile BFF 的认证体系基于 JWT Bearer，BFF 代理 Identity 的 OAuth 2.0 端点，前端只与 BFF 交互。BFF 不存储用户凭证，仅做请求转发和 token 代理。

## 认证架构

```
Taro 前端                    Mobile BFF                    Identity
────────                     ──────────                    ────────
POST /mobile/auth/login  ──► POST /connect/token       ──► 验证凭据
                         ◄── {access_token, refresh_token}
存储 token + deviceId

GET /mobile/* (Bearer)   ──► JWT 验证（Authority=Identity）
                         ◄── 200 OK / 401 Unauthorized

401 响应                 ──► POST /mobile/auth/refresh  ──► grant_type=refresh_token
                         ◄── {新 token}                     校验 device_id
重放原请求               ──► 用新 token 重试
```

## Token 类型

| Token | 存储位置 | 持久化 | 有效期 | 说明 |
|-------|----------|--------|--------|------|
| access_token | 前端内存变量 | 否 | 10 分钟 | 不写入持久存储，防泄露 |
| refresh_token | 本地存储 | 是 | 30 天 | 用于自动续期，绑定 device_id |
| device_id | 本地存储 | 是 | 永久 | 随机 GUID，登录时生成 |

## device_id 设备绑定

### 生成时机

用户首次打开应用时生成随机 GUID，存入本地存储（H5 用 localStorage，小程序/APP 用 Taro 异步存储）。

### 绑定流程

1. 登录时前端将 `deviceId` 随请求发送给 BFF
2. BFF 代理到 Identity 的 `/connect/token`，`device_id` 作为自定义参数传递
3. Identity 将 `device_id` 写入 JWT claim 和 refresh_token 绑定
4. 刷新时 Identity 校验 `device_id` 与签发时是否一致

### 设备隔离

- 每个设备独立登录，refresh_token 绑定 device_id
- 设备 A 的 refresh_token 不能在设备 B 上使用
- 刷新时 `device_id` 不匹配返回 `invalid_grant`

## 401 重试策略

```typescript
// Taro 前端 request.ts 中的重试逻辑
if (res.statusCode === 401 && auth && isTokenValid() === false) {
  const newToken = await tryRefreshToken()
  if (newToken) {
    // 用新 token 重放原请求
    header['Authorization'] = `Bearer ${newToken}`
    const retryRes = await Taro.request({ ... })
    return parseResponse<T>(retryRes)
  }
  // 刷新失败 → 清除 token，提示重新登录
  clearTokens()
  throw new Error('登录已过期，请重新登录')
}
```

### 重试条件

- 仅在 `auth=true` 的请求触发
- 仅重试一次，不循环重试
- 刷新失败立即清除本地 token

### 并发请求处理

多个请求同时收到 401 时，只发一次 refresh 请求。用 Promise 缓存正在进行的 refresh 请求，后续 401 共享同一 refresh 结果。

## BFF JWT 验证

BFF 使用 ASP.NET Core JWT Bearer 中间件验证 access_token：

```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = builder.Configuration["Identity:Authority"]; // K8s 内部
        // Audience 必须为 openfindbearings-api（与 Identity 签发令牌的 aud 一致）
        options.ValidAudience = builder.Configuration["Identity:Audience"] ?? "openfindbearings-api";
        options.RequireHttpsMetadata = false; // K8s 内部 HTTP
        options.TokenValidationParameters = new()
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
        };
    });
```

> 注：文档历史版本曾记载 `Audience = "api:mobile"`，实际代码已修正为 `openfindbearings-api`。

### 端点认证控制

| 模式 | 说明 |
|------|------|
| `AllowAnonymous()` | 公开端点，不检查 token |
| `RequireAuthorization()` | 需要有效 JWT |
| 默认（不指定） | 走全局 DefaultPolicy（需 JWT） |

## 登录流程详细

### 密码登录

```
前端 → POST /mobile/auth/login
  Body: { username: "手机号", password: "密码", deviceId: "GUID" }

  BFF 校验手机号格式（^1[3-9]\d{9}$），无效返回 400 PHONE_INVALID

BFF → Identity POST /connect/token
  grant_type=password
  username=手机号
  password=密码
  client_id=mobile-client
  scope=api:mobile offline_access
  device_id=GUID

Identity → BFF → 前端
  { accessToken, refreshToken, expiresIn: 600 }
```

### 注册

```
前端 → POST /mobile/auth/register
  Body: { username: "手机号", password: "密码", deviceId: "GUID" }

  BFF 校验手机号格式（^1[3-9]\d{9}$），无效返回 400 PHONE_INVALID

BFF → Identity POST /api/account/register
  创建用户（Identity 内部处理）

BFF → Identity POST /connect/token（自动登录）
  grant_type=password
  返回 token 对

前端 ← { accessToken, refreshToken, expiresIn: 600 }
```

### 短信登录

```
1. 前端 → POST /mobile/auth/send-code
     Body: { phone: "手机号" }
   BFF 校验手机号格式，无效返回 400 PHONE_INVALID
   BFF → Identity POST /api/sms/send-code

2. 前端 → POST /mobile/auth/login-sms
     Body: { phone: "手机号", code: "验证码", deviceId: "GUID" }
   BFF → Identity POST /connect/token
     grant_type=sms
     username=手机号
     code=验证码
     device_id=GUID
```

### 令牌刷新

```
前端 → POST /mobile/auth/refresh
  Body: { refreshToken: "旧token", deviceId: "GUID" }

BFF → Identity POST /connect/token
  grant_type=refresh_token
  refresh_token=旧token
  client_id=mobile-client
  device_id=GUID
  // Identity 校验 device_id 与签发时是否一致
```

### 登出

```
前端 → POST /mobile/auth/logout
  Body: { refreshToken: "当前refresh_token" }

BFF → Identity POST /connect/revocation
  token=refresh_token
  token_type_hint=refresh_token
  // 吊销 refresh_token，防止后续刷新
```

## 手机号格式校验

BFF 在所有涉及手机号的认证端点（register、login、login-sms、send-code）统一校验格式：

```csharp
private static bool IsChineseMobile(string phone)
    => Regex.IsMatch(phone, @"^1[3-9]\d{9}$");
```

无效手机号返回 HTTP 400：
```json
{ "success": false, "message": "手机号格式不正确" }
```

## AuthClient 扩展方法

| 方法 | 说明 |
|------|------|
| `SignUpAsync(username, password, deviceId)` | 注册新用户并自动登录获取 token |
| `LoginAsync(username, password, deviceId)` | 密码登录 |
| `LoginWithSmsAsync(phone, code, deviceId)` | 短信登录 |
| `RefreshAsync(refreshToken, deviceId)` | 刷新令牌（校验 device_id） |
| `SendSmsCodeAsync(phone)` | 发送验证码 |
| `GetUserInfoAsync(token)` | 获取用户信息 |
| `UpdateProfileAsync(token, nickname, pictureUrl)` | 更新 Identity 用户资料（昵称/头像） |
| `RevokeRefreshTokenAsync(refreshToken)` | 吊销 refresh_token（登出时调用） |

## BFF→API 内部令牌

BFF 调用 API 时统一附带请求头 `X-Internal-Token`（值取自配置 `Internal:ApiToken`），API 限流中间件识别匹配后豁免按 IP 的用户级限流。原因：API 无公网 ingress，全部 App 流量经单一 BFF Pod IP 转发，若按 IP 限流会误伤聚合流量。令牌经 K3s ConfigMap 注入 API 与 BFF 两侧，必须同值。

## 安全注意事项

- access_token 不持久化，仅存内存，防 XSS 窃取
- refresh_token 持久化但绑定 device_id，防跨设备盗用
- BFF 不存储任何凭证，仅做转发
- K8s 内部通信使用 HTTP（无需 TLS），公网域名使用 TLS
- BFF 的 CORS 仅允许 Taro H5 域名
- 认证端点受 IP 限流保护（10 次/分钟），防暴力破解
